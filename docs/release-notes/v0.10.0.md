# SiftWire v0.10.0

## Changed

- Remove the optional `siftwire-console` server, React application, UI-only dependencies, console installer, assets, and frontend checks.
- Use the existing `config.inspect_config` result for agent-formatted configuration overviews. No new skill, runner action, terminal UI, or persistent viewer is introduced.
- Keep configuration writes, operator archive commands, source selection, prepared email rendering, and delivery confirmation unchanged.

## Upgrade

Existing v0.9.x databases remain compatible. Install the v0.10.0 runner and same-tag skill; runner protocol v5 and the database schema are unchanged. Upgrades from v0.8.0 or earlier still require the [v5 compatibility reset](../runner-v5-reset.md).

The runner installer does not uninstall an existing console. If you installed it, stop and disable its service, then remove its binary, web assets, and service definition using your deployment paths. Leave the runner, brief scheduler, and database in place. Configuration inspection and edits remain available through the installed runner; saved briefs and collection evidence remain available through `runs list` and `runs show`.

## Verification

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.10.0`. The repository gate retains Rust formatting, strict lint, runner and evaluator tests, TypeScript checks, shell checks, skill validation, installer contracts, and a real release-binary clean installation. These checks do not claim a live brief delivery or broader agent success.
