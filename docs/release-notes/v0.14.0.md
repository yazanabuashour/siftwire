# SiftWire v0.14.0

## Changed

- Separate Releases, Blogs, News, Forums, and Sports in HTML, Markdown, and plain text. Count each populated category and omit empty headings.
- Share `max_delivery_items` across optional News and Forums without subtracting Required items. Sports remain outside the allowance.
- Retire Google News URL resolution. Preserve original feed links, reject the retired `url_canonicalization` source field, and remove `suppressed_unresolved` from live results.
- Skip selection when no candidates or optional capacity remain, remove redundant sorting, and keep Allow/Watch policies explicitly audit-only. Block enforcement remains unchanged.

## Upgrade

Install the v0.14.0 runner and same-tag skill using [the automation upgrade procedure](../automation.md#upgrade). Update process consumers together: runner protocol changes from v5 to v6. Requests containing `url_canonicalization`, including `none`, now fail strict decoding.

The database schema, source markers, durable jobs, outbox, and delivery history remain compatible. Existing prepared plans replay their saved bodies, and published Notes pages remain unchanged. No state reset or systemd entry point change is needed. See [the v6 contract changes](../runner-contract.md#upgrade-from-v5).

## Verification

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.14.0`. These gates cover collection and preparation capacity, section rendering, saved-plan replay, automation recovery, and release installation. They do not establish real agent judgment or live delivery.
