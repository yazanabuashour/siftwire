# SiftWire v0.15.0

## Changed

- Group RSS items with section `releases` under Releases alongside GitHub releases in HTML, Markdown, and plain text.
- Add optional `release_url_prefixes` for mixed RSS feeds. Matching release or security posts record section `releases`; other posts retain the source section. Original links, reporting thresholds, freshness, deduplication, and the shared optional allowance remain unchanged.
- Advertise `rss-release-routing/v1` under runner protocol v6. Existing selection and prepared-delivery request shapes remain compatible.

## Upgrade

Follow [the automation upgrade procedure](../automation.md#upgrade): stop collection, reconcile pending work, and preserve a consistent database backup plus the installed runner and skill before installing the v0.15.0 runner and same-tag skill.

Opening an exact schema-1 database transactionally upgrades it to schema 2 by adding empty release URL prefix lists. Configuration, markers, archived runs, prepared plans, and delivery evidence remain intact. Modified and unknown schemas remain rejected. Older runners cannot open schema 2; rollback requires restoring the pre-upgrade database backup with its matching runner and skill.

Require `rss-release-routing/v1` before configuring RSS release sections or URL prefixes. This release does not reclassify recorded run items, rerender saved plans, or rewrite published Notes pages. See [source fields](../runner-contract.md#source-fields) and [storage compatibility](../runner-contract.md#storage-selection).

## Verification

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.15.0`. The gates cover mixed-feed routing, optional capacity, recorded-section rendering, schema upgrade preservation, immutable delivery replay, and release installation. They do not establish real agent judgment or live delivery.
