# SiftWire v0.16.0

## Changed

- Add the `reader_priorities` brief option: free text describing the reader's interests, set with `set_brief_options` and stored with the rest of the operator configuration. Brief results include it when set, and the automation selector receives it with the candidates. The embedded prompt follows it over its general editorial guidance but not over its output contract or authority rules.
- Advertise `reader-priorities/v1` under runner protocol v6. Existing requests and results remain compatible.
- Always select with the embedded prompt. `SIFTWIRE_RENDER_PROMPT` no longer replaces it; a host-copied prompt would otherwise miss selection-contract changes in later releases.

## Upgrade

Follow [the automation upgrade procedure](../automation.md#upgrade) with the schedule stopped. After installing v0.16.0, confirm `reader-priorities/v1`, move the interests from any host prompt set through `SIFTWIRE_RENDER_PROMPT` into one `set_brief_options` request with `reader_priorities`, and check them with `inspect_config`. Then remove that variable, start one run, and remove the copied prompt after it succeeds. The database schema is unchanged.

## Verification

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.16.0`. The gates cover option storage, brief results, selector projection, and embedded-prompt installation. They do not establish real agent judgment or live delivery.
