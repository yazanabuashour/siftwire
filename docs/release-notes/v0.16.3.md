# SiftWire v0.16.3

## Changed

- Stop treating a long gap between collections as a stalled schedule. Use the host scheduler to detect missed runs. Durable collections still record `last_check`, and feed failures still produce health warnings. A previously active heartbeat warning resolves on the next durable collection.
- Configuration writes and brief collection now share validation code. Accepted option values have not changed. Invalid requests still make no writes; invalid stored settings still produce warnings and use defaults. No database migration or consumer update is required.

## Verification

A disposable feed and database exercise the 12-hour collection gap, atomic option rejection, and fallback for invalid stored values. Process tests cover JSON framing, zero optional capacity, and collected feed health.
