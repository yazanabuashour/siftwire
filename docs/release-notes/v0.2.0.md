# SiftWire v0.2.0

This release establishes the SiftWire name and promotes its one-shot JSON runner as the documented language-neutral integration contract.

## Changed

- Renamed the command, package, skill, repository URLs, environment variables, default database path, user agent, eval harness, installer, and release assets to SiftWire.
- Ported the runtime and agent-eval harness from Go to Rust while keeping runner actions, result compatibility fields, SQLite tables, migrations, public-source selection behavior, and delivery history compatible.
- Added the strict Rust and Clippy lint policy used by the Stackstead and Canonforge reference repositories, an exact pinned toolchain, locked dependencies, and native release builds for all supported platforms.
- Added `docs/runner-contract.md`, the process consumer `examples/inspect_config.rs`, and black-box process contract tests.
- Changed a repeated `record_delivery` call with the same run ID but a different message from an exit-1 storage failure to an exit-0 JSON domain rejection.
- Added `run_brief.delivery_message_scope=current_brief_only` and reject rendered `Current brief` or `Previous brief` wrappers before storage, preventing agents from contaminating current delivery history with prior output.
- Enforces the documented public-source boundary in the runner: credentials, loopback, private, link-local, metadata-service, non-public DNS results, and redirects to them are rejected before connection; proxy routing cannot bypass the resolver policy.
- Bounds decoded HTTP response bodies at the measured 16 MiB tripwire recorded in `receipts/http-response-size.json`.
- Creates new database directories and files with owner-only permissions, serializes schema migration, preserves nullable GitHub release-name fallback, and retains Go-compatible `-db` command-line spelling.
- Corrects delivery-history chronology for repeated messages and old-run retries, restores rolling four-source fetch concurrency without batch head-of-line blocking, and renders health source keys without shell-active Markdown delimiters.
- Simplified active documentation, the installed skill, skill validation, continuous integration, agent-eval workspaces, and direct-binary installation.

## Verification

- Repository Rust formatting, strict Clippy lint, tests, release build, shell checks, skill validation, and v0.1.8/v0.2.0 release-document checks pass through repository-owned scripts.
- Black-box tests verify runner framing, exits, configuration, local feed selection, exact delivery, retry behavior, and repeat runs.
- Installer tests verify direct-binary checksums, duplicate checksum rejection, version identity, and staged replacement.
- The minimal `examples/inspect_config.rs` consumer builds and runs using only the documented process contract.
- The 13-scenario production-agent eval passed every safety, capability, database, and hygiene check. Manual taste review accepts the current workflow for this rename while retaining its documented configuration and exact-delivery ceremony as known debt.
