# Siftwire v0.3.0

This release adds operator-facing inspection tooling: persisted per-run selection evidence, human CLI commands beside the JSON protocol, and an optional local web console.

## Changed

- Added the `brief_run_item` SQLite table so every successfully completed non-dry run persists its must-include items, candidates, and blocked-outlet drops with reasons and context.
- Added operator commands `source list`, `source add`, `runs list`, and `runs show --candidates --dropped --selected` with `--json` output; they sit outside the versioned `config|brief` process contract and are documented in the README.
- Added the optional `siftwire-console` binary and its React web application under `apps/web`; see `docs/console.md`. The console spawns the installed runner per request over the documented contract, never reads SQLite directly, binds loopback by default with an explicit bind override for trusted networks, rejects foreign Host headers to block DNS rebinding, kills timed-out runner processes, and exposes no run execution.
- Converted the repository to a Cargo workspace so console dependencies stay out of the released runner build.
- Removed retired product-name compatibility from database-path resolution, the installer, release validation, and documentation.

## Verification

- Repository gates pass through `scripts/ci.sh`: Rust formatting, strict Clippy lint, workspace tests, shell checks, skill validation, Prooflane shadow contract, installer contract, release build and clean-install test, plus web formatting, lint, typecheck, tests, and build.
- Black-box process tests verify runner framing and exits, configuration round trips, delivery idempotency and conflicts, dry runs leaving no run rows, persisted selection evidence through `runs show --json`, and source command validation.
- Console router tests verify API error mapping including domain rejections, unknown-run 404 responses, static index serving, and rejection of rebound Host headers.
