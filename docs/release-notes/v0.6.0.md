# SiftWire v0.6.0

## Changed

- Combine the console's latest and sent-history readers into one Brief page. Add a searchable, paginated picker shared with Activity, URL-backed selection, and links between exact briefs and run evidence.
- Group feed and publisher configuration under Sources. Use input-aware source editors, one effective reporting choice, compact publisher rows, optional notes, and explicit collection Save and Discard.
- Compute reporting policy in the runner and return it with configuration and recorded evidence. Preserve raw source fields, full-range priorities, source state, and existing deduplication behavior.
- Record stable item references in new delivery plans. Distinguish confirmed delivery, sports representation, unselected candidates, no delivery, and unknown historical outcomes without rewriting saved emails.
- Separate warnings and publisher annotations from exclusions. Preserve source labels in new fetch history rather than using today's configuration.
- Reject new publisher writes with overlapping enabled names or aliases. Existing conflicting configuration remains readable and retains its previous matching order until an operator resolves it.
- Extend `runs list` with delivery filtering, stable cursors, and literal archive search. Apply filtering before pagination and order the delivery archive by delivery time.

Update the runner, console binary, and web assets together. Opening the database adds a fetch-history label column with an empty default for old records. Existing source configuration, state, delivery plans, and email bodies remain unchanged. Refresh open console tabs after updating.

The `siftwire-runner/v2` process framing and existing actions remain unchanged. Result fields are additive; publisher collision validation is stricter. Console clients should use normalized mutation results and the new history metadata. See `docs/runner-contract.md`, `docs/run-history.md`, and `docs/console.md`.
