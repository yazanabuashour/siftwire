# SiftWire v0.8.0

## Changed

- Collect all optional RSS stories with a declared publication time in the preceding 24 hours. Keep original links and apply publisher policy locally. Optional feeds no longer use the Google News decoder or positional source markers.
- Report eligible, stale, undated, and future publication counts. Read publication elements through an XML parser rather than matching text inside comments or article content. Preserve historical new-item counts and label new unavailable counts honestly.
- Collapse identical absolute article URLs across sources. Match normalized headlines within their configured groups. Prefer the newer publication when choosing a duplicate representative. Suppress confirmed recent headlines across URLs, while allowing changed headlines on reused URLs to reach editorial selection.
- Require `siftwire-runner/v4` and `current-news/v1` for the matching skill and console. Keep Required RSS, GitHub releases, sports windows, immutable prepared bodies, and delivery recovery separate from optional-news selection.
- Remove legacy manual delivery writes, Observe writes, separate source commands, unused provider and extraction choices, release URL overrides, and the SiftWire-owned Prooflane wrapper. RSS and Atom XML use the `rss` source kind. Reporting thresholds own Required behavior.
- Explain current-news handling and saved resolver choices in the console. Preserve exact saved email HTML, explicit configuration saves, historical evidence, and decimal-string priorities across the full signed 64-bit range.
- Preserve HTTP parsing and cancellation errors, disable automatic request retries, and typecheck root frontend tooling alongside the app. Keep the existing cache, draft, and pending-write protections.
- Rewrite the active documentation and README around operator tasks. Add an actual console screenshot with fictional stories, a release, sports updates, and a source-health note. Document shared TypeScript policy ownership and distribution.

This release changes the public process contract. Follow [the v4 upgrade guide](../runner-v4-migration.md) before replacing an installed runner. Upgrades from v0.6.1 or another v2 release also need [the v3 source and delivery changes](../runner-v3-migration.md). No intermediate installation is required.

Update the runner, matching skill, console, web assets, and automated consumers together. Reconcile pending delivery before the upgrade. Keep consistent backups and preserve immutable plans rather than collecting replacement runs. Database initialization adds fetch-selection metadata without rewriting saved messages or optional source markers.

The root installer installs the runner. The matching source archive contains the optional console and web app. See [the console guide](../console.md) for its separate build and installation steps.

Browser checks and the README image use isolated synthetic data. They do not record a real email delivery. The fresh run followed narrow corrections to command recognition and rejection-message verification.

Captured-feed and selector checks establish the behavior of the measured inputs. They do not prove exhaustive discovery, event identity, article accuracy, equivalent source coverage, or a measured end-to-end speedup.
