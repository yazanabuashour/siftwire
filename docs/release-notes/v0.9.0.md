# SiftWire v0.9.0

## Changed

- Require `siftwire-runner/v5`, matching consumers, and a fresh database when upgrading from v0.8.0 or earlier. Remove old schema migrations, configuration read adapters, CLI aliases, delivery backfills, and inferred historical evidence. This is a compatibility reset, not an in-place upgrade.
- Keep supported source-selection semantics unchanged: optional RSS and Atom feeds use the rolling 24-hour publication window and original links; Required feeds retain latest-seen selection and configured canonicalization; GitHub releases remain Required; sports retain their recurring fixture and result windows outside normal candidate slots.
- Consolidate each source outcome in the engine: collected items, sports updates, selection and suppression evidence, health warnings, and any permitted next source marker. The runner applies durable writes and uses the same fetch status for result JSON and stored evidence. Current-news collection still neither reads nor advances source markers, and dry runs do not persist collection state.
- Confirm delivery from the immutable prepared plan. Storage derives the sent records and their timestamps inside the delivery transaction rather than accepting separate message and item copies from the runner. Exact saved bodies, evidence references, and idempotent confirmation remain required.
- Separate preparation eligibility from full archive reads. Before confirmation, an identical preparation retry returns the saved plan before loading selection inputs or rendering; different candidate indexes remain rejected. New plans retain concurrent-insert conflict protection, and delivered runs cannot prepare another plan. The refactor adds no process actions or agent calls and makes no performance claim.
- Require current evidence fields: sports use `sports_updates` and prepared bodies rather than duplicate ordinary `must_include` items; recent suppression uses `suppressed_recent`; archive outcomes use `delivery_status`; normal prepared items reference recorded evidence directly. The console accepts decimal-string source priorities and displays exact saved HTML without legacy rendering fallbacks.
- Allow explicit console DNS hostnames through `SIFTWIRE_CONSOLE_ALLOWED_HOSTS` for trusted-proxy routing. The comma-separated allowlist matches exact hostnames without case or port sensitivity and rejects invalid configuration at startup. It does not add authentication: retain a private network boundary or require authentication at the proxy, and prevent direct backend access. See the [console guide](../console.md#serve-through-a-trusted-proxy).

## Upgrade

Follow the [v0.9.0 fresh-database guide](../runner-v5-reset.md) before replacing an installation. Stop scheduled collection and reconcile pending delivery with the old runner. Preserve the old database and its matching runner for historical reads; do not edit schema versions to bypass compatibility checks.

Select a new external database with `SIFTWIRE_DATABASE_PATH` or `--db`. Install the v0.9.0 runner and matching skill, and update automated consumers together. If using the optional console, build and install it and its web assets from the matching tag or source archive. The root installer installs only the runner; register the same-tag skill separately.

Inspect and approve current source and publisher configuration before writing it through `config`. There is no operational-state import path. A fresh database has no sources, delivery history, or latest-seen state: recent-delivery suppression starts empty, and Required feeds follow fresh-source selection. No intermediate release installation is required.

Require `siftwire-runner/v5` and the capabilities each caller uses before writes or collection. `prepared-delivery/v1`, `sports-updates/v1`, and `current-news/v1` remain available. Use `--db`, not `-db`, and `rss` for both RSS and Atom feeds. Retired Observe/audit, `always_report`, and unsupported processing choices have no compatibility adapters. See the [runner contract](../runner-contract.md) for current fields and retry rules.
