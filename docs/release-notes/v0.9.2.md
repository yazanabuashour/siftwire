# SiftWire v0.9.2

## Changed

- Render prepared HTML through the standalone public `email-ui` crate, pinned to an immutable git revision. SiftWire keeps ownership of edition and date labels, time zones, grouping, counts, and empty-section policy; the shared crate owns presentation only.
- Preserve the existing email markup and styles, link fallbacks, decorative images, and source-health notice. Frozen synthetic fixtures protect exact HTML bytes captured before extraction, including morning/evening editions, escaped content, image handling, and empty sections.
- Preserve supported query and fragment backslashes during shared URL validation. The delivery-preparation regression test verifies the exact query-backslash link and immutable replay through the process contract.
- Keep the runner protocol, skill, database schema, source selection, Markdown and plain-text bodies, final answers, stored-plan replay, confirmation, and optional console behavior unchanged. Existing prepared plans are not rerendered.

## Upgrade

Existing v0.9.0 and v0.9.1 databases and configuration remain compatible. Install the v0.9.2 runner and register the same-tag skill; no database reset, state import, or console rebuild is needed for this patch. The release binary includes the renderer, so no separate `email-ui` executable or installation is required. Upgrades from v0.8.0 or earlier still require the [v5 compatibility reset](../runner-v5-reset.md).

## Verification

The shared-renderer implementation passed repository CI. All four [frozen HTML fixtures](../../crates/siftwire/tests/fixtures/email/README.md) remained byte-identical, and the process tests verified preparation, exact saved-plan replay, and confirmed archive HTML. The query-backslash regression failed against the initial shared dependency and passed after the corrective pinned revision. These receipts establish synthetic parity, not real email delivery or exhaustive mail-client compatibility.

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.9.2` for the release revision. The release workflow validates the exact tag, builds the platform assets, verifies checksums, and publishes attestations before release.
