# SiftWire v0.9.3

## Changed

- Reject optional sports candidates with promotional livestream headlines or routine sports watch guides, and optional news URLs with embedded data/script query loaders before selection. Normalize compatibility Unicode for headline checks and retain dropped evidence with `promotional_livestream`, `sports_watch_guide`, and `embedded_loader_url` reasons. This narrow admission rule is not publisher verification or a general spam detector.
- Clarify sports editorial policy: fixtures and scores come from structured schedules; optional team news should cover confirmed major developments rather than routine previews, recaps, odds, watch guides, or rumors. Operator thresholds and the automation selector remain operator-owned configuration.
- Include the previously unreleased correctness fixes listed in the changelog: collection locking, fractional timestamp ordering, non-object request rejection, explicit runtime failures, console deadlines and IPv6 Host handling, ESPN date queries, and multi-turn evaluation and hygiene checks.

## Upgrade

Existing v0.9.x databases remain compatible. Install the v0.9.3 runner and same-tag skill. The runner protocol, schema, tracked sources, sports windows, time zones, immutable prepared plans, and confirmation contract remain unchanged. Existing saved plans replay without applying new admission rules. Operator-owned selector and source-threshold changes are separate from the runner release.

## Verification

Run `mise exec -- ./scripts/ci.sh` and `mise exec -- ./scripts/validate-release-docs.sh v0.9.3`. The polluted-feed regression covers exclusion evidence, rejected selection, legitimate reporting, and recurring fixtures/results with a configured time zone. These are synthetic checks, not a delivery receipt or proof of comprehensive spam rejection.
